# 机型目录：建档、填写与发布

机型目录记录协会及成员的航模、它们的来历和飞行故事。每份档案对应一架实际航模；同一机型的不同机体分别建档，退役后保留原档案。

日常补充资料只需要修改 Markdown 和照片，不需要修改网页程序。模板、说明文件不会作为航模展示。

目录在每次打开或刷新网页时，将全部航模条目放在同一个列表中随机排列；站内进入详情再返回时保留本次顺序。文件名、购入日期和档案内容不会因此改变。随机结果偶尔可能与上一次相同。

## 1. 找到文件并新建档案

| 需要做什么 | 文件位置 |
| --- | --- |
| 新建一架航模的档案 | 复制 [航模档案/_template.md](航模档案/_template.md) |
| 修改现有档案 | 打开 `航模档案` 内对应的 `.md` 文件 |
| 添加航模照片 | 放入项目根目录的 `发布资源/机型目录配图` |
| 修改栏目名称 | 项目根目录的 `网站内容/公共文字.json` 中的 `栏目.aircraft` |

在资源管理器中进入 `网站内容/06_机型目录/航模档案`，复制 `_template.md` 并粘贴到同一文件夹。重命名副本，例如 `魔翼90-01.md`，再用 VS Code 或其他文本编辑器打开。

保留原模板供下一位维护者复制。正式档案的文件名不能以下划线开头；确认后缀是 `.md`，不是 `.md.txt`。资源管理器可在“查看 → 显示 → 文件扩展名”中显示后缀。

先保留 `status: draft`。文件保存时使用 UTF-8 编码。已存在的飞机直接修改原档案，不要每次维修或更新都再复制一份。

## 2. 看懂模板，避免错填一行

最上方两条 `---` 之间是文章信息，下方是故事正文。不要删除这两条分隔线。

以 `#` 开头的字段注释说明的是它**下面的字段行**。只修改冒号右侧，不把答案写进注释，不把字段名改成中文。例如：

```text
# 类型：固定翼、穿越机、直升机、多旋翼或其他。
category: 固定翼
# 一句话介绍特点或最值得讲的故事，供目录卡片展示。
summary: 从大胡子手中购入的迅飞双40mm 电动涵道 SU-57。
```

使用英文冒号 `:`，列表中使用英文逗号 `,`。普通文字无需加引号；当前读取程序会把引号作为文字保留。单个字段值放在同一行，多段故事写到正文。未知字段留空，例如 `battery:`；名单和相册没有内容时保留 `[]`。

正文的 `<!-- … -->` 是隐藏提示，可以保留。实际故事写在 `-->` 之后的新段落，不能写在注释内部，否则不会显示。

## 3. 字段填写及网页位置

新建时先填 `id`、`title`、`model`、`category`、`summary`，有照片时填 `cover` 和 `cover_alt`。这些是编辑建议，程序目前没有自动完整性检查，发布前需要自行检查。其他资料知道多少写多少。

| 字段 | 如何填写 | 网页用途 |
| --- | --- | --- |
| `id` | 唯一的英文、数字和短横线，例如 `xunfei-su57-01`；复制后必须换成新 id，发布后不要改 | 详情地址的识别码 |
| `title` | 清晰的显示名称，例如“迅飞双40mm 电动涵道 SU-57” | 卡片和详情标题 |
| `model` | 厂牌及实际机型名称 | 详情资料 |
| `nickname` | 这架飞机的昵称，没有则留空 | 详情资料 |
| `airframe_id` | 实际机体编号，没有则留空；这里不能填“固定翼” | 详情资料 |
| `category` | 固定翼、穿越机、直升机、多旋翼或其他；同类保持同一种写法 | 卡片和详情，不按类别分组 |
| `summary` | 一句话特点或故事；这里不能填图片地址 | 卡片和详情简介 |
| `cover` | 封面图片的网页地址，见下一节 | 卡片缩略图及详情封面 |
| `cover_alt` | 描述照片实际画面；这里不能填归属 | 图片替代文字 |
| `ownership` | 经确认的归属，如“协会公共航模”或“个人” | 仅详情显示，目录卡片不显示 |
| `service_status` | 在用、维修中、退役等实际状态；保留已确认的表述 | 卡片和详情 |
| `status_updated` | 最近确认机体状态的日期，格式 `YYYY-MM-DD` | 详情资料 |
| `acquired_date` | 购入、制作完成或获赠日期；允许 `2024`、`2024-09`、`2024-09-21` | 详情资料，不作为当前目录排序依据 |
| `acquired_date_label` | 说明上述日期的含义，如“购入时间” | 日期字段的显示名称，有日期才展示 |
| `acquisition` | 来源的一句话经过，如“从大胡子手中购入。” | 详情资料 |
| `wingspan` | 翼展及单位，例如 `900 mm` | 详情资料 |
| `dimensions` | 其他尺寸、测量对象及单位，例如“机长 800 mm” | 详情资料 |
| `weight` | 单位及是否含电池，例如“起飞重量 500 g（含电池）” | 详情资料 |
| `power` | 已确认的电机、电调、螺旋桨或涵道配置 | 详情资料 |
| `battery` | 电池类型、节数、容量等，按实机配置填写 | 详情资料 |
| `purpose` | 实际用途，如新人训练、科普展示或竞赛 | 详情资料 |
| `members` | 可公开的姓名或称呼，如 `[张同学, 李同学]`；具体角色写进故事 | 详情的参与同学 |
| `gallery` | 补充照片地址列表，见下一节 | 详情相册，按填写顺序显示 |
| `source_title` | 公开来源的标题，无来源则留空 | 详情来源说明 |
| `source_url` | 上述来源的真实网页链接，无链接则留空 | 查看完整报道入口；只有链接没有标题时不显示 |
| `status` | 整理中为 `draft`，确认后为 `published` | 控制稿件发布，不表示飞机状态 |
| `visibility` | 确认可公开时为 `public`；其他值不会进入构建 | 控制公开范围 |

同一机型有两架，可以使用不同的 `id` 和昵称来区分。成员个人飞机不自动视为协会资产；已有教程中的机型图片也不能证明具体机体的身份或当前状态。

购入日期和状态确认日期是两件事，只知道其中一个就只填对应字段。状态有变化时，更新 `service_status`、`status_updated` 和“今天的它”，历史经历留在故事中。

## 4. 放照片并填写地址

先把可公开的照片复制到项目根目录的 `发布资源/机型目录配图`，再在档案中引用。只放进文件夹不会自动显示图片；构建只复制被内容引用的资源。

| 电脑中的文件 | 档案使用的网页地址 |
| --- | --- |
| `发布资源/机型目录配图/SU-57.jpg` | `/aircraft-assets/SU-57.jpg` |
| `发布资源/机型目录配图/全球Ultimate.jpg` | `/aircraft-assets/全球Ultimate.jpg` |
| `发布资源/机型目录配图/L-39 (4).jpg` | `/aircraft-assets/L-39%20%284%29.jpg` |
| `发布资源/官网配图/照片.jpg` | `/assets/照片.jpg` |

不要填写 `D:\...` 的本地绝对路径。网页地址使用正斜杠 `/`，文件名和扩展名的大小写与原文件一致。中文文件名可以直接写；空格写为 `%20`，左括号写为 `%28`，右括号写为 `%29`。新图片可取不带空格和括号的名称，例如 `l39-first-flight.jpg`，减少输入错误。

### 封面

```text
cover: /aircraft-assets/L-39%20%284%29.jpg
cover_alt: HSDJET 120mm EDF L-39 航模
```

卡片图片等比例填满图片框、居中裁切，不会拉伸；重要主体尽量位于图片中间。详情封面等比例完整展示。`cover_alt` 最好根据实际画面写得更具体，不要填写未经确认的场景。

### 相册

所有地址写在同一行，使用英文逗号分隔：

```text
gallery: [/aircraft-assets/L-39%20%281%29.jpg, /aircraft-assets/L-39%20%282%29.jpg, /aircraft-assets/L-39%20%283%29.jpg]
```

相册会提供打开原图的入口。与封面完全相同的地址不会重复进入相册；如果同一照片已插入故事正文，就不要再填入 `gallery`，避免重复展示。当前相册自动生成“档案标题 · 照片序号”的图注；需要具体说明时，把照片放进正文。

### 故事中的照片

在对应段落后空一行，再写：

```markdown
![L-39 航模](/aircraft-assets/L-39%20%281%29.jpg)
```

方括号描述画面，圆括号放图片地址。不要在段落中间插入图片代码。替换或删除照片前，在网站内容中搜索文件名，确认是否有其他页面引用。

## 5. 写故事和相关链接

模板的六个小节供选择，不必全部写满。没有正文、只有注释的二级小节会在详情中隐藏，也可以直接删除。正文使用 `##` 作为章节标题，`###` 作为章节内的事件标题；不要把正文写在最上方字段区。

```markdown
## 认识这架飞机

这是一架迅飞 SU-57 航模，采用双40mm 电动涵道动力。

## 它怎样来到协会

这架航模从大胡子手中购入。
```

后续可补充为什么选这架飞机、谁参与调试、首飞遇到什么、哪次维修最难忘。日期不确定就省略日期，不补写不存在的情节。参数变更时说明对应时期，避免把旧配置当成当前配置。

相关链接使用现有内容的 `id`，不是 Markdown 文件名：

```markdown
[魔翼 90 制作教程](?article=moyi90)
[某次活动报道](?kind=news&id=该新闻的真实id)
[相关项目记录](?kind=projects&id=该项目的真实id)
[另一架航模](?kind=aircraft&id=另一份档案的真实id)
```

后三行是格式示例，使用前替换成真实 id，点击验证能打开。没有相关资料就删除这一节。

## 6. 本地预览草稿

在资源管理器中打开项目根目录，在空白处右键选择“在终端中打开”。若已打开 PowerShell，先进入项目目录：

```powershell
cd "D:\Users\10754\Documents\GitHub\aero-association-site"
```

第一次预览时安装项目依赖；电脑需要已经安装 Python：

```powershell
python -m pip install -r requirements-static.txt
```

然后构建草稿预览并启动服务器：

```powershell
python build_static_site.py --preview
python -m http.server 8000 --directory dist
```

打开 [机型目录预览](http://127.0.0.1:8000/?page=aircraft)。保持服务器窗口运行，结束时按 `Ctrl+C`。`--preview` 只额外加入机型目录中 `draft` 且 `public` 的档案，不会加入其他栏目的草稿，也不会展示非 public 内容。模板以下划线开头，始终不展示。

修改后保存文件，在另一个终端进入同一项目目录，重新运行 `python build_static_site.py --preview`，再刷新浏览器。不需要每次重启服务器；显示旧内容时可以按 `Ctrl+F5` 强制刷新。

检查列表上的标题、分类、简介、图片裁切及状态，点击进入详情检查资料、故事和相册；缩窄浏览器窗口检查手机布局。个人归属不会显示在目录卡片中，但会显示在详情里。

## 7. 确认后发布

1. 确认机型和具体机体身份、归属、故事、状态日期，以及姓名和照片的公开范围。
2. 检查 id 唯一、图片存在、链接可打开；空参数可以保留，正文只留下给访客看的内容。
3. 把要发布的档案改为 `status: published`，保留 `visibility: public`。只改飞机的 `service_status` 不会发布稿件。
4. 在本地执行正式构建，不使用 `--preview`，确认发布版本显示该档案，其他草稿不显示：

```powershell
python build_static_site.py
node --test --test-isolation=none tests/navigation.test.cjs tests/static-paths.test.cjs tests/aircraft.test.cjs
```

5. 刷新本地页面检查正式效果，然后按 [参与维护](../../CONTRIBUTING.md) 提交 Pull Request。说明新增或更新了哪架飞机、资料来源及已检查的效果。
6. 合并到 `main` 后由 GitHub Actions 构建并发布。仅保存文件或本地预览不会更新线上网站。

提交 Markdown、引用的照片和必要说明；`dist` 是生成目录，不手动编辑它。正式发布流程使用默认构建命令，不能把草稿预览构建产物直接用于发布。

若暂时撤下档案，把 `status` 改回 `draft` 并重新正式构建、提交更新。已经公开过的资料不会因此从 Git 历史或他人副本中消失，所以 draft 也不要写内部或敏感信息。

## 8. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 草稿不出现在本地目录 | 是否用 `--preview` 构建；是否为 `status: draft` 和 `visibility: public`；文件名是否以下划线开头 |
| 发布后没有档案 | 是否为 `published` 和 `public`；是否重新构建；是否已合并并完成线上部署 |
| 内容跑到错误位置 | 注释说明的是下面一行；分类写 category，简介写 summary，图片写 cover，归属写 ownership |
| 图片打不开或构建提示资源不存在 | 对照真实文件名、大小写、扩展名与路径；检查空格和括号编码，不能用本地 D 盘路径 |
| 图片边缘被裁掉 | 目录封面使用居中填充；换主体居中的照片，详情可查看完整封面和相册 |
| 故事写了却看不到 | 是否写进了 HTML 注释；是否保存并重新构建；是否修改了正确档案 |
| 出现两个相同档案或点开内容不对 | 检查两份文件是否用了相同 id；每架必须有唯一 id |
| 日期显示含义不对 | 购入日期填 acquired_date，日期含义填 acquired_date_label，状态确认日期填 status_updated |
| 参数为空 | 未知就留空，详情不会显示空字段，不必猜测 |
| 服务器提示端口被占用 | 先尝试打开已有的 8000 预览；也可改用 `python -m http.server 8001 --directory dist`，浏览器端口相应改为 8001 |
| 系统找不到 python | 检查 Python 是否已安装并加入 PATH；若电脑支持 py，可把命令中的 python 换成 py |

更详细的 Markdown 和公共文字说明见 [网站内容编辑说明](../README.md)，初次提交见 [GitHub 零基础入门](../../GitHub零基础入门.md)。
