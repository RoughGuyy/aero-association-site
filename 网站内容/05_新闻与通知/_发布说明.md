# 官网内容稿

这里是宣传部和活动部维护官网内容的统一入口。保存 Markdown 后，官网会自动读取其中 `status: published` 且 `visibility: public` 的内容；草稿和内部内容不会显示。

| 目录 | 维护方 | 内容 |
| --- | --- | --- |
| `05_新闻与通知/活动新闻` | 宣传部 | 已发生的活动新闻、活动记录 |
| `05_新闻与通知/活动通知` | 活动部 | 即将发生的活动通知、报名信息 |
| `03_项目与竞赛/项目记录` | 宣传部/技术部 | 竞赛项目和已确认的制作记录；成员飞机展示需说明归属，不默认自制 |

使用方法：复制相应目录中的 `_template.md`，用日期和简短标题命名，例如 `2026-09-迎新飞行体验.md`。先保持 `status: draft`，内容和公开授权确认后再改为 `published`。

字段留空比猜测更好。照片原件统一保存在 `source_materials`，确认发布时再把对应图片复制/处理到 `发布资源/官网配图`，并在 `cover` 或 `gallery` 中填写 `/assets/文件名`。不要把 `source_materials` 的内部路径直接写进公开页面。

公开读取接口：

- `GET /api/content/news`
- `GET /api/content/notices`
- `GET /api/content/projects`
- `GET /api/content/{栏目}/{内容 id}`

官网中的位置：

- 新闻和通知分别进入“新闻与通知”页面，也在首页显示最近三条；新闻列表展示简介和配图，点击标题打开官网内的活动介绍与照片。
- 项目稿进入“项目与竞赛”下方的项目记录列表。
- 往届成员或独立团队的历史报道仍放在 `projects`，填写 `record_type: history`，页面会将其单列为“往届成员与相关团队”，不与协会项目记录混排。`project_type` 用作可见分类，如“往届成员经历”或“历史团队报道”。普通项目不填 `record_type` 即可。
- 一条内容的地址为 `/?kind=news&id=内容id`、`/?kind=notices&id=内容id` 或 `/?kind=projects&id=内容id`。
- 新闻的 `cover` 是列表缩略图，`cover_alt` 填写具体画面说明。详情页也会显示这张图；如果正文已用 `![图注](/assets/相同文件名)` 放过它，则不在详情开头重复显示。`gallery` 可补充更多图片。没有对应活动照片时留空，不用别的年份或活动凑图。
- 通知中的活动日期、开始/结束时间、地点、报名截止、联系方式和报名链接按已填写的字段展示。
- 不填写的字段不会显示。`status` 或 `visibility` 缺失时不会发布。

### 日期与原报道

- `date` 用于列表排序。新闻默认显示“活动日期”，通知默认显示“发布日期”，项目默认显示“记录日期”。
- 只知道原报道日期时，填写该日期，同时设置 `date_label: 报道日期`，不要将其写成实际活动日期。跨日活动可另填 `event_date` 为完整时间范围，`date_label` 可以写“活动开始”。
- 有原报道时填写 `source_title`、`source_name`、`source_date`、`source_url`。详情底部统一显示来源和“查看完整报道”入口，在新标签打开原文。链接不确定时留空，只保留来源名称、标题和日期，不显示“待补”等内部备注。
- 来源是成绩册等文件时，可填 `source_link_text: 查看官方成绩册`，替换默认的“查看完整报道”按钮文字。
- 原报道事实可以用自己的语言简要整理，并注明出处。整篇转载、图片转载和未成年人肖像分别核对授权，不由“网上能看到”推定可以直接使用。
